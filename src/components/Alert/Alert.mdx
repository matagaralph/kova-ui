### Action placement

Actions are automatically, intelligently positioned in the alert by default.

You can force a specific position with the `actionsPlacement` prop, by passing either `'end'` or `'bottom'`. This would be ideal for long alert messages with multiple actions.

Alert provides an indicator icon by default, which changes based on the `color` passed to the component (e.g., success, warning, error).

You can override the default indicator by passing a custom icon to `indicator`.

## Best practices

- Use `<Alert>` for persistent, in-context messages about a section or page. Use a `<Badge>` for short status labels.
- Match `color` to intent: `danger` for errors, `warning` or `caution` for risks, `success` for confirmations, and `primary` or `info` for neutral notices.
- Keep `title` short and put supporting detail in `description`.
- Limit `actions` to one or two labeled buttons, and use `actionsPlacement="bottom"` for long messages with multiple actions.
- Keep the default `indicator` unless a custom icon communicates the message more clearly.

## Accessibility

- Alerts with `color="danger"` render with `role="alert"`, so screen readers announce them when they appear. Other colors have no live region role.
- The default indicator is decorative. Make sure `title` or `description` conveys the message without relying on color or icon.
- Use labeled buttons in `actions` for dismissal or follow-up steps so they are reachable by keyboard and have clear accessible names.
