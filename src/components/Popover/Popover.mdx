## Examples

### Sizing the popover

The popover can be sized with any combination of `width`, `minWidth`, or `maxWidth`. All popovers default to a `minWidth` of `300px`, and a `maxWidth` of Radix's viewport detection.

<Canvas of={PopoverStories.NaturalSizing} />

### Open on hover

Use `showOnHover` to create popovers that appear on hover and focus events. This should be used sparingly and with clear intention.

By default, hover popovers will not alter the focused element on the page, nor restore focus to the trigger on close. However, if interactive content is present in the popover, and `tab` is used to navigate into the popover, focus will be restored to the trigger on close.

<Canvas of={PopoverStories.Hover} />

### Using the controller

You can access `usePopoverController()` controller context from components within `Popover.Content`. The hook exposes two methods, `close()` and `shake()`. They do exactly what you think they do.

- Attempting to submit an empty form calls the `shake()` method
- After async submission occurs (faked loading state), the `close()` method is called to close the popup imperatively.

<Canvas of={PopoverStories.Controller} />

### Nesting
All floating UI components in Kova UI can be infinitely nested by relying on `z-index: auto;` and natural stacking order.

Additionally, `esc` keypresses are handled independently as a stacking order.

## Best practices

- Use `Popover` for contextual content and lightweight forms. Use `Menu` for lists of actions, and `Dialog` for focused tasks that should block the page.
- Wrap a focusable element, like a `Button`, in `Popover.Trigger`. It renders its child directly.
- Use `showOnHover` sparingly, and never hide essential actions behind hover alone.
- Size content with `width`, `minWidth`, and `maxWidth` instead of overriding styles with `className`.
- Use `usePopoverController()` to `close()` after a successful submit, or `shake()` to reject an invalid one.

## Accessibility

- The trigger receives `aria-expanded` and `aria-controls` from Radix, and the content renders with `role="dialog"`.
- On open, focus moves to the popover container (unless `autoFocus={false}` or `showOnHover` is set). Shift+Tab from the container moves focus to the last focusable element inside.
- `Esc` closes the topmost popover only, so nested popovers close one at a time.
- Focus returns to the trigger on close. Hover popovers only restore focus when the user tabbed into them.
