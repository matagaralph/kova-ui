DataTable renders rows of data as a native, accessible table. Describe the columns once and pass the data, and it handles row headers, sorting, column widths, and row groups for you. When you need full control over the markup, compose the same pieces yourself with `Table`.

## Usage
```jsx
import { DataTable, Table, createColumnHelper } from "kova-ui/components/DataTable";
```

<Canvas of={DataTableStories.Base} additionalActions={[

Each row needs a unique `id`, or pass `getRowId` to pick another field. Wrap the table in `Table.Container` with a `Table.Title`, and point `aria-labelledby` at the title's `id`.

## Examples

### Columns
A column sets its header and which `field` of the row to show. Fields can reach into nested objects with dots, like `owner.name`. Use `renderCell` to render anything else, like a badge or a formatted date.

`createColumnHelper` gives you typed columns, so `field` and `renderCell` know the shape of your rows.

```tsx
const columnHelper = createColumnHelper<Project>()

const columns = [
  columnHelper.column({ header: "Project", field: "name", rowHeader: true }),
  columnHelper.column({
    header: "Status",
    field: "status",
    renderCell: (row) => <StatusBadge status={row.status} />,
  }),
]
```

Here, `renderCell` shows each project's status as a `Badge`.

### Sorting
Set `sortBy` on a column to make it sortable. Pass `true` to compare values directly, or name a strategy:

- **`alphanumeric`:** natural order for text with numbers, so "Item 2" comes before "Item 10".
- **`datetime`:** compares `Date` objects and timestamps.
- **`basic`:** compares values with `<` and `>`. This is what `true` uses.

Set `initialSortColumn` and `initialSortDirection` to sort the table when it first renders. Empty values always sort last.

### Column widths
Each column accepts a `width`:

- **`grow`** (default): fills the free space, and is never narrower than its widest cell.
- **`growCollapse`:** fills the free space, and can shrink narrower than its content.
- **`auto`:** as wide as its widest cell. Avoid it when the content changes a lot, since the layout shifts.
- **A length**, like `140` or `"20%"`: a fixed width.

Use `minWidth` and `maxWidth` to set limits.

## Best practices

- Give every table a visible title with `Table.Title`, and connect it with `aria-labelledby`.
- Mark the column that identifies each row, like a name, with `rowHeader`.
- Only make columns sortable when sorting helps people find something. Sort by the most useful column to start.
- Right-align numbers, and keep text left-aligned.
- Use `Table.CellPlaceholder` for missing values rather than leaving cells blank.
- Paginate long tables instead of rendering hundreds of rows.
- Keep row actions consistent across rows, and move rarely used ones into a menu.

## Accessibility

- DataTable renders a native `table`, so screen readers announce rows, columns, and headers, and table navigation keys work.
- Column headers use `scope="col"`, and `rowHeader` columns render as `th` with `scope="row"`.
- Sortable headers contain a button. The header's `aria-sort` reports the current direction, and the button's description says what pressing it does, like "Sort descending".
- Each group heading is a `th` with `scope="colgroup"` that spans every column. Its accessible name is the label and row count, like "Active, 3 rows". Pass `aria-label` in the group data to translate it.
- In grouped tables, every cell's `headers` lists its group, row, and column headers, so screen readers announce the group as people move between cells.
- When the table overflows, its scroll container becomes a labelled region in the tab order.
- Pagination is a `nav` landmark labelled by `aria-label`. The current page has `aria-current`, and the range ("Showing 1 through 10 of 120") is announced when it changes.
- Previous and next stay focusable on the first and last page, but are marked `aria-disabled`.

## Reference

<h3 id="datatable-root" data-heading-label="DataTable">`DataTable`</h3>

| Prop | Type | Description |
| --- | --- | --- |
| `data` | `Array<Row \| RowGroup>` | The rows to show, as rows, row groups, or a mix of both. Each row needs a unique `id` |
| `columns` | `Array<Column>` | The columns of the table and the fields they show |
| `aria-labelledby` | `string` | The id of the element that labels the table, usually `Table.Title` |
| `aria-describedby` | `string` | The id of the element that describes the table, usually `Table.Subtitle` |
| `cellPadding` | `"condensed" \| "normal" \| "spacious"` | The space around each cell's content. Defaults to `"normal"` |
| `initialSortColumn` | `string \| number` | The `id` or `field` of the column to sort by at first. The data must already be sorted by it in ascending order |
| `initialSortDirection` | `"ASC" \| "DESC"` | The direction of the initial sort |
| `externalSorting` | `boolean` | Keeps the order of `data` when a column is sorted, for sorting on the server. `onToggleSort` still fires |
| `onToggleSort` | `(columnId, direction) => void` | Called each time a sortable header is pressed, with the column id and the new direction |
| `getRowId` | `(row) => string \| number` | Returns the unique id for a row. Defaults to `row.id` |

<h3 id="datatable-column" data-heading-label="Column">`Column`</h3>

| Property | Type | Description |
| --- | --- | --- |
| `header` | `string \| () => ReactNode` | The column header |
| `field` | `string` | The field of the row to show, with dots for nested fields |
| `id` | `string` | A unique id for the column. Defaults to `field` |
| `renderCell` | `(row) => ReactNode` | Renders the cell for a row |
| `rowHeader` | `boolean` | Treats the column's cells as row headers |
| `sortBy` | `boolean \| string \| function` | Makes the column sortable. Pass `"alphanumeric"`, `"basic"`, or `"datetime"` to pick a strategy, or a function `(a, b) => number` |
| `align` | `"start" \| "end"` | Horizontal alignment of the column's content |
| `width` | `string \| number` | `"grow"`, `"growCollapse"`, `"auto"`, or a fixed length. Defaults to `"grow"` |
| `minWidth` | `number \| string` | The narrowest the column can shrink to |
| `maxWidth` | `number \| string` | The widest the column can grow to |
