## Examples

### Limits

Use `min` and `max` to limit date ranges to a specific timeframe.

You can also use `maxRangeDays` to limit the range of days allowed.

<Canvas of={DateRangePickerStories.Limits}/>

### Shortcuts

Use the `shortcuts` array to provide a list of quick data shortcuts.

When a given shortcut is selected, its label is displayed in the trigger.

<Canvas of={DateRangePickerStories.Shortcuts} />

### Month stepper

Enable a stepper view in the trigger by passing `triggerStepperUnit`. When the selected date matches the unit (e.g., a month), the trigger view will convert into the stepper view.

When the range does not match the stepper unit, the normal trigger is displayed.

## Best practices

- Use `DateRangePicker` when people need a start and end date. For a single date, use `DatePicker`.
- Offer `shortcuts` for common ranges such as "Last 7 days". Each `getDateRange` should return a fresh range so relative dates stay current.
- Use `maxRangeDays` to cap range length instead of validating after selection.
- Set `triggerStepperUnit="month"` for monthly reporting views, so people can step between months from the trigger.
- Enable `clearable` only when an empty range is valid. Clearing calls `onChange` with `null`.

## Accessibility

- The trigger has `role="button"`, `aria-expanded`, and `aria-haspopup="dialog"`. Space, ArrowDown, and ArrowUp open the calendar; Enter does not, so it can still submit a form.
- Escape closes the calendar. Opening the calendar does not move focus into it.
- Days and shortcuts are native buttons, and dates outside `min`, `max`, or `maxRangeDays` are disabled.
- Shortcuts are hidden below the `md` breakpoint, so every range must also be selectable from the calendar.
- The trigger's accessible name is its displayed range or placeholder. Provide a visible label next to the picker.
