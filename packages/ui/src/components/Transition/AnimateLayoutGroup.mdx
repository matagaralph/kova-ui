### Overview

`<AnimateLayoutGroup>` is an abstraction around `<TransitionGroup>` specifically designed for rendering lists of components, while batteries-included transition animations that can also animate `height` and `width` of transitions.

All of the same properties from `<Animate>` are supported here, as well as new properties for customizing the timing of layout transitions - `layoutEnter`, `layoutExit`, and `layoutMove`.

### When to use

`<AnimateLayoutGroup>` is great for animating lists of components that should naturally affect layout of surrounding DOM nodes.

## Best practices

- Key each list item by a stable id, not its array index, so the right item enters and exits.
- Use padding on list items instead of margin, so spacing animates with the item size.
- Use `layoutExit` with a `delay` so items fade out before the list closes the gap.
- Set `dimension="width"` for horizontal lists, like chips or toolbars.
- Use `AnimateLayout` instead when only one item is shown at a time.

## Accessibility

- `AnimateLayoutGroup` adds no roles or ARIA attributes. Add list semantics yourself when the items form a list.
- Removed items stay in the DOM until their exit transition ends. Move focus to a nearby item or control when the focused item is removed.
- There is no built-in `prefers-reduced-motion` handling. Use shorter or opacity-only transitions when users prefer reduced motion.
- Announce added or removed items with an `aria-live` region when the change is not otherwise obvious.
