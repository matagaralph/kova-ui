## Best practices

- Use `<Badge>` for short, static labels like statuses, counts, or categories. Use `<Button>` for anything clickable and `<Alert>` for messages.
- Keep content to one or two words.
- Match `color` to meaning, such as `success` for active states and `danger` for failures, and use the default `secondary` for neutral metadata.
- Use `variant="soft"` (default) in dense layouts and reserve `solid` for statuses that need extra emphasis.
- Set `size` to fit the surrounding text, and use `pill` for counts or tag-like labels.

## Accessibility

- Badges render a plain `<div>` with no role, so their text is read as regular content.
- Don't rely on `color` alone to convey meaning; the badge text should describe the status.
- When a badge contains only an icon or loading indicator, include text or a visually hidden label that describes it.
