Filter lets users narrow down a list by typing free text and qualifiers such as `status:done` or `-label:urgent`. While typing, it suggests qualifiers and their values, highlights recognised qualifiers, and validates the query. The **Filter** button opens an advanced dialog for building the query without learning the syntax.

Qualifiers come from `providers`. Each provider describes one key: its display name, the values it accepts, and how to suggest them.

## Usage
```jsx
import { Filter } from "kova-ui/components";
```

const providers = [
  {
    key: "status",
    displayName: "Status",
    type: "select",
    options: [{ value: "todo", label: "To do" }, { value: "done", label: "Done" }],
  },
  { key: "assignee", displayName: "Assignee", getSuggestions: (query) => searchPeople(query) },
  { key: "priority", displayName: "Priority", type: "number", negatable: false },

### Query syntax

| Syntax | Meaning |
| --- | --- |
| `key:value` | Matches items where `key` is `value` |
| `-key:value` | Excludes items where `key` is `value`, unless the provider sets `negatable: false` |
| `key:a,b` | Matches either value, for providers with `allowsMultiple` |
| `key:"two words"` | Quotes values that contain spaces or commas |
| `key:>5`, `key:1..5` | Comparisons and ranges for `number` and `date` providers |
| Anything else | Free text, available as `query.text` |

Use `parseFilterQuery(value, providers)` to parse a query outside the component, for example from the URL on page load.

## Best practices

- Always provide a `label`, and reflect the query in the URL so filtered views can be shared and restored.
- Apply the query on `onSubmit` when filtering is slow, or on `onParse` for instant filtering of local data.
- Name the active filters in empty states, and offer `Filter.Revert` to clear them.
- Keep provider keys short and lowercase. Add `aliases` for common alternatives.
- Prefer `type: "select"` with `options` when the set of values is known, so invalid values are caught.

## Accessibility

- The input is a Base UI `Autocomplete` with `role="combobox"`. Arrow keys move through suggestions, `Enter` picks the highlighted one, and `Escape` closes the list.
- `Enter` with no highlighted suggestion submits the query.
- The label is linked to the input, and stays available to assistive technology when `visuallyHideLabel` is set.
- Validation messages are announced with `aria-live="polite"`, linked with `aria-describedby`, and mark the input with `aria-invalid`.
- Qualifier highlighting is decorative and hidden from assistive technology.
- Announce changes to the results with a `role="status"` region, as in the list example.

<h3 id="filter-provider" data-heading-label="Provider">`FilterProvider`</h3>

| Prop | Type | Description |
| --- | --- | --- |
| `key` | `string` | Qualifier key, as in `key:value` |
| `displayName` | `string` | Name shown in suggestions and the advanced dialog |
| `icon` | `ComponentType` | Icon shown next to the qualifier suggestion |
| `aliases` | `string[]` | Other keys that resolve to this provider |
| `type` | `"select" \| "text" \| "number" \| "date"` | Kind of value accepted. Defaults to `"text"` |
| `options` | `FilterSuggestion[]` | Suggested values, and the accepted values for `"select"` |
| `getSuggestions` | `(query, context) => FilterSuggestion[] \| Promise` | Loads value suggestions |
| `allowsMultiple` | `boolean` | Accept comma separated values |
| `negatable` | `boolean` | Allow `-key:value`. Defaults to `true` |
| `validate` | `(values) => string \| undefined` | Returns a message when the values are invalid |
