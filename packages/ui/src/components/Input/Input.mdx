## Examples

### Variants
Use `variant` to stylize the input.

### Sizing & roundness

Sizing of the input is controlled with `size` and `gutterSize` props. `size` sets the input to a specific control `height`, and `gutterSize` sets the horizontal padding.

Each `size` provides default values for `gutterSize`, as well as `font-size`. Each of these values can be overridden independently.

<Canvas of={InputStories.Sizing} sourceState='hidden' />

### Start adornment

Use `startAdornment` to add content to the start of an input, like a search icon.

Ideally, the spacing will look pretty good by default. If you need to customize the spacing:
- `gutterSize` determines the amount of spacing on the edges of the container, which you can fine-tune as needed.
  - If you need precise spacing not supported by `gutterSize`, use negative left margin on your adornment directly (e.g., `-ml-2`).
- The spacing between the adornment and the input is controlled with `gap` on the container, which you can customize as needed with Tailwind classes.

<Canvas of={InputStories.StartAdornment} />

### End adornment

Use `endAdornment` to add content to the end of an input, like a clear button.

The same spacing guidance from `startAdornment` applies here.

End adornments are most commonly actions that are tucked tightly into the container frame. In these cases, you'll likely reach for negative right margin (e.g., `-mr-2.5`) to achieve that aesthetic.

<Canvas of={InputStories.EndAdornment} />

### Disabled

Use the `disabled` prop to disable the input, greying it out and preventing user interactions.

<Canvas of={InputStories.Disabled} />

### Invalid

Use the `invalid` prop to mark the input as invalid. You decide how this state is removed, whether that's through `onFocus`, `onChange`, an `onSubmit` handler, etc.

Default visual styles will be applied, based on the `variant`. Additionally, `[data-invalid]` is applied to the container for custom styling.

<Canvas of={InputStories.Invalid} />

### Auto select text

Pass `autoSelect` to select all the text in the input, which is handy next to a copy action. This prop behaves like an imperative action when toggled and allows selection to change.

<Canvas of={InputStories.AutoSelect} />

### Autofill extensions

By default, autofill extensions are prevented by `Input`. For the occasions where you want browser extensions to be present, pass `allowAutofillExtensions` to remove the disabling.

When `name` is passed, `autoComplete` is passed, or `type` is set to `"password"`, this value will default to `true`.

<Canvas of={InputStories.AutofillExtensions} />

Use `opticallyAlign` with either `"start"` or `"end"` to offset the gutter of the input.

## Best practices

- Use `Input` for single-line text. For multi-line text, use `Textarea`; for picking from known options, use `Select`.
- Match `size` with neighboring controls such as `Button` so heights line up.
- Use `startAdornment` for context like a search icon, and `endAdornment` for compact actions like a clear button.
- Set `type`, `name`, and `autoComplete` on form fields so browsers and password managers can autofill them.
- Clear `invalid` as soon as the value is corrected, and show the error message as text near the input.

## Accessibility

- Renders a native `input`, so standard keyboard behavior, `disabled`, and `readOnly` work as expected. All other `input` attributes are passed through.
- Clicking the container outside the input focuses the input, except when clicking a button inside an adornment.
- Always provide a label: a `label` with `htmlFor` matching `id`, or `aria-label` when there is no visible label.
- `invalid` only changes styling. Also set `aria-invalid` and link the error text with `aria-describedby`.
- Give icon-only buttons in adornments an `aria-label`.
