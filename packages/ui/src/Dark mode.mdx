## Overview

Light and dark mode are fully supported, but your app is in control of how the attribute is applied and persisted.

To set a view mode, apply a `[data-theme]` attribute to the `html` element of your DOM.

```html
<html data-theme="dark">
  <!-- ... -->
</html>
```

Light and dark mode can also be nested within your content:

```html
<html data-theme="dark">
  <body>
    <div>Dark mode content (root scope)</div>
    <div data-theme="light">Light mode content (nested scope)</div>
  </body>
</html>
```

## Tailwind

Tailwind is configured to look for the `[data-theme]` attribute, and will work as expected with dark mode classes.

For more details, refer to the [Tailwind documentation](https://tailwindcss.com/docs/dark-mode).

```html
<div class="bg-white dark:bg-black">
  <!-- ... -->
</div>
```

## JavaScript

Import the theme helpers from `kova-ui/theme`. They follow the same conventions as libraries like `next-themes`: the selected theme can be `"light"`, `"dark"`, or `"system"`, and `"system"` follows the operating system setting. The choice is saved in `localStorage`, stays in sync across tabs, and updates when the operating system setting changes. No provider is needed.

### `useTheme`

Reads and updates the theme from a component, and re-renders when it changes.

```tsx
import { useTheme } from "kova-ui/theme"

const ThemeSwitcher = () => {
  const { theme, resolvedTheme, systemTheme, setTheme } = useTheme()
  // theme: "light" | "dark" | "system" (the user's choice)
  // resolvedTheme: "light" | "dark" (what's on screen)
  // systemTheme: "light" | "dark" (the operating system setting)
}
```

For example, a theme switcher built with `SegmentedControl`:

```tsx
import { SegmentedControl } from "kova-ui/components"
import { useTheme, type Theme } from "kova-ui/theme"

const ThemeSwitcher = () => {
  const { theme, setTheme } = useTheme()

  return (
    <SegmentedControl<Theme> aria-label="Theme" value={theme} onChange={setTheme}>
      <SegmentedControl.Option value="light">Light</SegmentedControl.Option>
      <SegmentedControl.Option value="dark">Dark</SegmentedControl.Option>
      <SegmentedControl.Option value="system">System</SegmentedControl.Option>
    </SegmentedControl>
  )
}
```

### `setTheme`

Selects a theme, applies it to the `html` element, and saves it. It also works outside React, and every component using `useTheme` updates.

```tsx
import { setTheme } from "kova-ui/theme"

setTheme("dark")
setTheme("system")
```

### `getTheme`, `getSystemTheme`, and `resolveTheme`

Read the theme outside React.

```tsx
import { getSystemTheme, getTheme, resolveTheme } from "kova-ui/theme"

getTheme() // "light" | "dark" | "system"
getSystemTheme() // "light" | "dark"
resolveTheme(getTheme()) // "light" | "dark"
```

## Avoiding a flash of the wrong theme

React applies the theme after the page loads, so a server-rendered page can briefly show the wrong theme. Add `themeScript` to the start of `<head>` to apply the saved theme before the first paint.

```tsx
// Next.js app/layout.tsx
import { themeScript } from "kova-ui/theme"

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <head>
        <script dangerouslySetInnerHTML={{ __html: themeScript }} />
      </head>
      <body>{children}</body>
    </html>
  )
}
```

`suppressHydrationWarning` is needed because the script sets `data-theme` on `html` before React hydrates. For a client-only app, such as Vite, call `setTheme` or `useTheme` early instead, or inline the same script in `index.html`.

## Migrating from the document theme helpers

`applyDocumentTheme`, `getDocumentTheme`, and `useDocumentTheme` have been replaced:

| Before | After |
| --- | --- |
| `applyDocumentTheme("dark")` | `setTheme("dark")`, which also saves the choice |
| `getDocumentTheme()` | `resolveTheme(getTheme())` |
| `useDocumentTheme()` | `useTheme().resolvedTheme` |

You no longer need your own store for persistence, `"system"` support, or listening to operating system changes.
