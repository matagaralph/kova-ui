Every page of these docs is also plain Markdown, written for agents as much as for people. Live examples become their full source, as `tsx` code blocks, so an agent sees code it can copy as-is.

## llms.txt

[`/llms.txt`](/llms.txt) links to the Markdown of every page, grouped like the sidebar. Point an agent at it first, and it fetches only the pages it needs.

[`/llms-full.txt`](/llms-full.txt) is every page in one file.

## Markdown pages

Add `.md` to any page's URL for its Markdown.

```text
https://ui.amashona.com/docs/components/switch.md
```

When the site runs on a server, a request for a page with `Accept: text/markdown` gets the Markdown too.

## Tell your agent about Kova

Add a few lines to your project's `AGENTS.md` (or `CLAUDE.md`), so every session starts from the same rules.

```md title="AGENTS.md"
## UI

This app uses Kova UI, Amashona's design system.

- Docs: https://ui.amashona.com/llms.txt. Read a component's page (add `.md` to its URL) before using it.
- Import components from `kova-ui/components`, icons from `@kova-ui/icons`, and `Markdown` and `CodeBlock` from `@kova-ui/markdown`.
- Compose components from their parts, like `<Switch><Switch.Thumb /></Switch>`. Don't hand-roll a control Kova has.
- Style with Kova's tokens and Tailwind utilities (`bg-surface`, `text-secondary`, `border-default`), never raw colors.
- Brand colors come from the `--kova-*` variables, set once in the global stylesheet.
```

## Tips

- **Ask for the page first.** "Read the Select page, then add a country picker" gets better results than relying on what a model remembers about other libraries.
- **Keep examples as the source of truth.** Every example on these docs is a complete file that imports only from Kova and React, so it runs as written.
- **Review accessibility.** The components handle the behavior, but names are yours, so check that every control has a label or `aria-label`.
